# Micro Decisions

- 2026-04-20: Preserved `mantle watch` wrapped-command exit status by returning the agent process code explicitly and forcing cleanup trap success. Reason: EXIT-trap postamble checks must not flip successful runs to exit code 1.
- 2026-04-20: Updated proxy-log correlation fallback so multiple unmatched `*.log` files no longer fail `TraceStore.poll_once`; unmatched traces continue ingesting eBPF/native events without proxy payload mapping unless explicitly configured. Reason: ambiguous shared proxy logs should not block dashboard DB freshness for non-LLM traces.
- 2026-04-20: Added `MANTLE_HOST_HOME` compose mount indirection and propagated it from `Makefile`/`bin/mantle` to keep `.mantle` bind mounts anchored to invoking user home under sudo flows. Reason: `${HOME}` under sudo resolves to `/root`, causing split trace/db roots and confusing watch/dashboard path mismatches.
- 2026-04-19: Added Docker Compose command fallback (`docker compose` plugin first, `docker-compose` fallback with `DOCKER_API_VERSION=1.44`) in Makefile and `bin/mantle`, plus explicit Docker daemon access preflight errors. Reason: host environments vary, and compose-v1 against newer Docker engines needs API pinning to avoid `ContainerConfig` failures and cryptic stack traces.
- 2026-04-19: For `docker-compose` v1 targets in Makefile, switched `build` to `down --remove-orphans` before `up --build` and added service-level `rm -fs` before `up` on `serve`/`proxy`/`daemon-start`. Reason: docker-compose v1 recreate path can crash with `KeyError: 'ContainerConfig'` on newer Docker Engine versions.
- 2026-04-19: Added explicit proxy passthrough routes for `POST /v1/responses` and `POST /responses` in `mantle/litellm_proxy/proxy.py`, including trace-log writes via existing proxy logger. Reason: LiteLLM `1.9.x` proxy server does not expose Responses API routes, which caused Codex/OpenAI Responses clients to fail with 404 during `mantle watch`.
- 2026-04-19: Hardened responses passthrough request forwarding with a strict upstream header allowlist (`authorization`, `content-type`, `accept`, OpenAI/Stainless metadata headers) instead of broad header pass-through. Reason: extra client hop-by-hop/non-API headers caused upstream edge rejection (`400 Bad Request` HTML from Cloudflare) for `POST /v1/responses`.
- 2026-04-19: Optimized container build footprint by enabling `apt-get --no-install-recommends`, disabling pip cache in image builds, and pinning `litellm[proxy]==1.9.4` in runtime requirements. Reason: reduce disk pressure and dependency churn during iterative compose rebuilds.
- 2026-04-19: Replaced env-driven runtime folder selection with a fixed repo-local `.mantle/{obs,config,logs}` layout across runtime resolvers and launch scripts. Reason: eliminate split capture roots and path drift from stale shell overrides.
- 2026-04-19: Switched local/default observability layout from `./obs` to `./logs/obs` (dev) and `~/.mantle/obs` (non-dev), with a hard migration policy and no read fallback to legacy `./obs`. Reason: production-ready path conventions and explicit dev/prod separation without requiring elevated permissions for local runs.
- 2026-04-19: Added centralized runtime bootstrap (`mantle/runtime/*`) for environment schema validation, writable path preflight checks, and structured runtime logging with correlation fields. Reason: enforce fail-fast startup behavior and remove silent logging configuration drift across server/agent/proxy.
- 2026-04-19: Moved LiteLLM proxy runtime from top-level `litellm_proxy/` to `mantle/litellm_proxy/` and centralized proxy config under `.mantle` (dev) or `~/.mantle` (non-dev). Reason: package-local ownership and unified runtime configuration roots.
- 2026-04-19: Removed package-local LiteLLM config template `mantle/litellm_proxy/config.yaml`; proxy config scaffold is now owned by runtime path bootstrap and created only at `.mantle/config/litellm_proxy.config.yaml` when missing. Reason: single source of truth for proxy config and explicit no-overwrite behavior for user-managed config.

- 2026-04-19: Added `Debug Info` controls to rendered trace event rows (including coalesced file folder views) that open a formatted JSON modal for the rendered payload object, and fixed coalesced file-group titles to recompute touched-file counts from the merged tree. Reason: operators need first-class event introspection and accurate aggregate labels when consecutive file groups are collapsed.
- 2026-04-19: Coalesced consecutive file-touch system groups into one folder tree row per process scope in display-trace renderers (Raw Events tab + source process popup). Reason: event views should expose one aggregated file-operations view per process level instead of fragmented consecutive file rows.
- 2026-04-19: Added a compact/detailed trace toggle in replay Raw Events and source-pid popup views, with compact mode hiding a configurable hidden-event-type list (default: `fd_open`, `fd_close`, `fd_write`, `fd_write_ret`) stored in browser localStorage. Reason: low-signal fd open/close/write noise obscures primary trace activity, but operators still need one-click access to full-fidelity detailed events.
- 2026-04-18: Added a generalized event-view API/UI path (`/api/traces/{trace_id}/display-trace` + frontend `display_trace(pid=None, start_timestamp=None, end_timestamp=None)`) and a Replay "Raw Events" tab that reuses the same renderer as source-pid popups. Reason: all event viewers now share one recursive pid/timestamp-scoped rendering path and expose direct-vs-nested syscall metrics consistently.
- 2026-04-18: Updated LLM boundary extraction in `mantle/analysis/llm_parser.py` to treat proxy `direction=response` records as primary turn boundaries, attaching request context only when available by URL/time ordering. Reason: current proxy logging can emit response-only records; request-paired-only boundary extraction drops valid turns and undercounts SQLite turn rows.
- 2026-04-18: Added an explicit active-trace control channel from `run_intercepted_agent.sh` to LiteLLM proxy (`POST /mantle/active-trace`) and switched proxy logging to write into the current trace filename when active. Reason: under the single-trace-at-a-time runtime constraint, direct trace-named proxy files provide deterministic 1:1 mapping with eBPF trace files and remove per-port log stitching ambiguity.
- 2026-04-18: Updated `run_intercepted_agent.sh` to execute watched agent commands as invoking user (`SUDO_USER`) while keeping eBPF capture privileges at root. Reason: running agent CLIs as root under `mantle watch` bypassed user-scoped configs/auth (for example `~/.codex/config.toml`) and could silently route traffic away from the configured local LiteLLM proxy.
- 2026-04-18: Added deterministic TCP destination capture in `mantle/capture/ebpf.py` by parsing `connect(2)` sockaddr (IPv4/IPv6) into `net_connect` events (`connect4`/`connect6` parse path). Reason: endpoint extraction from `/proc` socket tables is race-prone for short-lived/nonblocking connects and can emit unresolved `fd=*` placeholders.
- 2026-04-18: Disabled MITM interception in `run_intercepted_agent.sh`/`bin/mantle watch` and shifted watch runtime to eBPF-only capture while keeping LiteLLM as the LLM endpoint. Reason: MITM proxying masked real destination IP/port values in BPF network telemetry and reduced trace fidelity.
- 2026-04-18: Added `file_rename_ret` to strict BPF event normalization in `mantle/capture/events_model.py`. Reason: real capture streams emit rename return events; rejecting them halted poll-loop ingestion for otherwise valid traces.
- 2026-04-18: Switched post-processing payload ingestion to proxy-only (`llm_capture_source=proxy`) in `mantle/ingest/store.py` and `mantle/server/app.py`; removed MITM payload-source selection from active ingest paths while keeping deterministic proxy log selection. Reason: MITM payload capture is deprecated and disabled in watch runtime, so correlation and SQLite turns/tool-calls must derive from LiteLLM proxy logs.
- 2026-04-15: Added explicit layer contracts under `docs/contracts/` for kernel probe stream, eBPF JSONL, correlation+SQLite ingest, downstream replay APIs, frontend rendering, and an end-to-end pipeline map. Reason: agent-driven changes need stable interface gates so cross-layer schema drift is caught before implementation diverges.
- 2026-04-15: Added a Makefile `build` pipeline (`preflight-sudo`, `preflight-foundation`, `install-system-deps`, `install-python-deps`, `verify-mantle`) for demo readiness with idempotent dependency setup. Reason: setup must fail early on missing Linux/Python foundations, require explicit sudo for system-level prerequisites, and avoid reinstalling unchanged dependencies while ensuring `bin/mantle` is functional.
- 2026-04-14: In `mantle/capture/events_model.py`, `file_read`/`file_write`/`file_delete`/`file_rename` now accept empty string path fields during validation. Reason: real BPF capture events can emit empty paths for some file operations, and rejecting them stops ingestion.
- 2026-04-14: Added `file_snapshot` to supported capture event types. Reason: snapshot records are emitted by the current capture path and should pass strict transformation.
- 2026-04-14: In replay detail rendering, append an explicit `assistant_text` action section when only usage metadata exists but `turn.response_text` is present. Reason: some MITM schemas emit usage/action metadata without assistant-text sections, which made final responses disappear in the UI.
- 2026-04-14: In `replay_turn_detail`, attach deterministic source metadata (`section.sources`) for `tool_outputs` context values using trace-wide tool-call source catalogs. Reason: text-only tool outputs in later turns may not carry `tool_call_id`, so frontend-only exact string matching is not reliable.
- 2026-04-14: The SQLite `event` table now stores canonical AbstractEvent columns (`line_no`, `pid`, `ppid`, `child_pid`, `path`, `src`, `dest`, `bytes_count`, `exec_path`, `command`, `argv_json`, `label`) plus `event_kind`. Reason: downstream readers should query structured fields directly without payload decoding.
- 2026-04-14: For system events, SQLite `payload` now stores only residual/unmapped fields from transformed events (for example `flags`, `fd`, snapshot metadata), and mapped canonical fields are removed. Reason: payload should be an extension bucket, not the primary schema.
- 2026-04-14: Removed container-only repo assets (`Dockerfile`, `docker-compose.yml`, `docker/entrypoint.sh`) and Docker-focused README guidance. Reason: current development workflow is native-only, so keeping inactive container scaffolding adds maintenance overhead and stale setup paths.
- 2026-04-14: In `bin/mantle`, `serve` now defaults to `127.0.0.1` unconditionally (removed `/.dockerenv` host switch). Reason: container-first host auto-detection is no longer needed after Docker workflow removal.
- 2026-04-14: Added per-event capture confidence metadata in `mantle/ingest/store.py` using three labels: `tier1_payload_exact`, `tier2_payload_mapped`, `tier3_network_only`. Reason: network endpoint attribution quality must be explicit in UI/API and not implied as certain.
- 2026-04-14: Kept the destination near-match tolerance at 2 seconds for MITM interval mapping and classified those matches as `tier2_payload_mapped` instead of exact. Reason: near-window matching is heuristic and should not be presented as exact confidence.
- 2026-04-14: Added `/api/traces/{trace_id}/capture-quality` endpoint that reports overall tier, per-tier counts, unresolved-fd ratio, and inference sources. Reason: operators need a single trace-level quality signal for demo and audit readiness.
